# DoCut v0.44 — 템플릿 갤러리 미리보기 및 데이터 링크 복원 정합성

**기준:** v0.43 `main` commit `920a18f614168bdf0f8219670d95dd356d4d1952`

## 문제 및 해결

### A. 엑셀 원본 변경 시 연결 차트 데이터가 저장·재열기 과정에서 갱신되지 않을 수 있는 문제

기존 `assets/data_motion.js`의 프로젝트 정규화 루프는 `materialize(el, ds, el.dataBinding)`를 계산했지만 **반환된 새 객체를 프로젝트 배열에 대입하지 않았다**. 따라서 XLSX/CSV 자료가 바뀌어도 차트가 이전 `data.values`를 표시하거나 독립 HTML에서 오래된 수치를 출력할 수 있었다.

- **변경:** 연결된 블록만 `pg.elements[i]=materialize(...)`로 교체. 내부에서 원본을 복제하므로 원래 프로젝트 JSON의 직접 변형은 없음.
- **동작:** 프로젝트를 열거나, 저장 전 정규화하거나, 같은 데이터 ID의 셀이 변경되면 현재 숫자로 다시 계산. 다른 페이지에서 같은 dataset을 공유하는 차트도 각각 재계산.
- **안전성:** 결측 숫자를 0으로 바꾸지 않는다. 음수, 0, 360포인트 바/선 스타일 및 장비별 팔레트를 보존. 자료가 없거나 수식 계산값이 누락된 경우 오류 안내.
- **검증:** 코드/모델 단위 샘플에서 저장 JSON에는 [12,-5,0]가 있지만 원본 셀을 27로 갱신한 경우, 정상화 및 내보낸 HTML이 [12,27,0]으로 갱신됨.

### B. 회사별 디자인 상세 미리보기에서 도형이 60개부터 잘리는 문제

기존 `assets/page_kits.js`의 `previewMarkup`은 모든 종류의 템플릿을 `MAX_BLOCKS=60`으로 미리보기 했음. 회사별 6페이지는 60개를 넘는 요소도 허용하지만, 실제 미리보기는 도형/차트의 뒷부분이 누락되어 사용자에게 구조를 잘못 보여줄 수 있었다.

- **변경:** `page.designIdentity`가 존재하는 전문 템플릿의 **상세 미리보기 120요소**까지 렌더, 기본·개인 템플릿 상한 60 유지.
- **성능:** 갤러리 카드와 6페이지의 축약 썸네일은 22요소까지만 그림. 큰 캔버스만 상세 120요소 전체 표시.
- **정확성:** 각 편집 블록의 글꼴 크기와 행간을 `cqw` 컨테이너 단위로 변환해 계층을 더 가깝게 유지. `container-type:inline-size`를 적용해 작은 화면에서도 상대적 비율이 유지된다.
- **안전성:** 글자 입력은 `C.escapeHTML`, 색상값은 정규식 검증, 글자 크기·행간은 숫자 클램핑. `<img onerror>` 같은 텍스트가 실행되지 않도록 유지.
