## 1. 목적과 제품 원칙

- **보고서는 영상이다:** 16:9 페이지 = 장면, 콘텐츠 = 캡션/레이어, 표시 효과 = 타임라인, 논리 전개 = 시퀀스.
- **구조를 먼저 잡고 내용을 채운다:** 문서 목적·장수에 따라 전개 탭을 자동 지정하고, 이후 사용자가 수정·고정할 수 있어야 한다.
- **사실 검증을 디자인보다 우선한다:** 숫자가 검증되지 않은 경우 샘플로 표시하고 AI 프롬프트에는 실제 수치를 만들지 말라고 지시한다.
- **실무 문서의 재사용:** 완료한 HTML을 나중에 불러와 편집할 수 있어야 한다. DoCut 전용 HTML의 양방향 무손실을 먼저 보장하고, 범용 HTML은 안전한 구조 변환으로 시작한다.
- **모션 품질과 자원 효율:** 각 개체에 최대 3개의 효과를 허용하되 매끄러운 가감속, 유한 반복, 화면 이탈 시 중단을 기본으로 한다.

## 3. UX 기준

**상단:** 프로젝트 제목/저장·가져오기/보고서 출력/재생.  **왼쪽:** 스토리보드·요소·디자인 3탭.  **중앙:** 고정 비율 캔버스, 직접 드래그/리사이징.  **아래:** 8초 기준 모션 타임라인.  **오른쪽:** 텍스트·포지션·폰트·컬러·모션 3슬롯.

기본 디자인은 다크 스튜디오와 Wood Brown 무채색 보고서의 대비이며, 카드에는 강한 색 채움보다 그림자와 공간감을 우선 사용한다.

## 4. 전개 템플릿 (기본 제목)

- 3장: 배경 및 목적 → 핵심 분석 → 결론 및 제언
- 4장: 현황 진단 → 핵심 문제 → 대안 비교 → 개선 방안
- 5장: 핵심 요약 → 현황과 배경 → 문제 및 근거 → 대안 비교 → 권고 및 실행
- 6장: 핵심 요약 → 문제 정의 → 데이터 분석 → 외부 사례 → 대안 및 권고 → 실행 계획
- 7~8장: 벤치마크·대안·실행·기대 효과 단계 추가

페이지 수 변경 시 **사용자가 수정한 탭명은 보존**, 자동 탭명만 다시 제안한다. 페이지 콘텐츠를 자동으로 훼손하지 않는다.

## 5. 효과 사양

`fade`, `rise`, `slide-left`, `slide-right`, `zoom`, `blur`, `rotate`, `pulse`, `glow`, `float`, `exit`, `none`.

- 요소당 0~3 슬롯 / 슬롯별 종류·지연(0~8000ms)·지속(100~3000ms).
- 동일 요소의 슬롯은 순서대로 실행되고, 다른 요소는 병렬 배치할 수 있다.
- 이징 `cubic-bezier(.22,1,.36,1)`을 기본 적용.
- `requestAnimationFrame` 기반 무한 루프와 탭 뒤쪽에서 계속 도는 배경 효과를 금지.
- 미리보기 닫기/페이지 전환/브라우저 숨김 시 애니메이션 객체를 취소.

## 6. 범위 제외 및 후속 승인 없이 가능한 개발

- 범용 HTML의 픽셀 정확도 역변환은 DOM/캔버스 추정기와 검증 UI가 갖춰진 이후 확장.
- 차트의 Excel/CSV 열 매핑, AI API 직접 호출, PPTX 내보내기, 비디오 렌더링, 공동 편집은 V0.8~V1.x에서 순차 반영.
- 자동 빌드·일반 Push에서 Actions 실행, 설치 EXE/APK/ZIP 생성 금지. 사용자 실기 검증 직전 또는 명시 요청 시에만 필요한 단일 빌드를 허용.
