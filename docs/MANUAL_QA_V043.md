# DoCut v0.43 실기검증 사전 체크리스트 — **아직 실행하지 않음**

> **검증 상태: NOT_RUN.** 사용자가 실기검증을 나중에 하겠다고 지정했으므로 이 문서는 확인용 계획서이다. Chrome/Brave 실제 화면 캡처·기기 조작·운영 배포를 통과했다고 주장하지 않는다. 데스크톱 EXE·ZIP은 대상이 아니다. DoCut의 최종 제품은 독립 실행형 HTML이다.

## 실행 게이트

1. 코드 최종 일괄 커밋의 SHA를 GitHub `main`과 대조한다.
2. Vercel 배포 준비 상태(설정 `vercel.json`의 자동 배포 금지)를 확인한다.
3. 사용자가 실제 테스트를 요청한 시점에 **최종 커밋 1회만** Vercel에 수동 배포한다. 브랜치/커밋/사이트가 서로 같아야 한다.
4. 운영 도메인·배포 전용 주소·배포 SHA·READY 상태를 함께 기록한다. 운영 주소가 오래된 빌드를 가리키면 배포 완료로 보고하지 않는다.
5. 필요한 경우에만 최종 운영 사이트에서 아래 시나리오를 수행한다. GitHub Actions·EXE·APK·ZIP 자동 생성은 전면 금지.

## 1. 20개 템플릿 / 120페이지 전수

각 팩의 1~6페이지를 **모두** 확인한다. 각 페이지는 1280×720 화면 기준, 독립 16:9 구조로 표시된다.

| 케이스 | 동작 | 통과 조건 |
|---|---|---|
| T01 목록 | 전문 보고서 갤러리 열기 → 01~20 모두 클릭 | 제목·타입·디자인 계열 20개 정확히 노출 |
| T02 6페이지 삽입 | 각 회사에서 `전체 팩 삽입` | 각 6장 생성, 이전 페이지/자료 보존 |
| T03 독립성 | 01·02·03·04·05·10·16·17·20 나란히 비교 | 배경색만 바꾼 같은 카드/박스 재사용 없음 |
| T04 16:9 | PC 1280×720·1920×1080·소형 390×844 | 글자/도형/차트/아래 주석이 잘리지 않음 |
| T05 편집 | 제목·부제·선·표·차트 클릭→이동·크기 변경 | native 편집 동작, 박스 ID 유지 |
| T06 페이지 이동 | 위쪽 얇은 페이지바 1~6 전환 | 현재 페이지 유지, 왼쪽 첫 탭 회귀 안 함 |
| T07 우클릭 | 페이지와 객체 각각 우클릭 | 자체 메뉴·잠금·해제·편집 작업 분리 |
| T08 되돌리기 | 수정 3회→Undo/Redo→저장→다시 열기 | 텍스트·차트 값·템플릿 정체성 유지 |
| T09 고유 팔레트 | 차트 없는 표지에서 새 Excel 차트 추가 | 소속 회사 전용 차트 스타일 자동 추천 |
| T10 HTML 출력 | 회사별 전체 6페이지 독립 HTML | 원본과 유사한 시각/레이아웃, 모든 값 유지 |

**시각 QA 증거:** 원본 보고서 공식 PDF에서 각각 표지·본문·주요 차트·표·각주 쪽을 선별. PDF는 공식 출처와 페이지 번호 기록. DoCut 화면은 회사별 6페이지를 동일 뷰포트에서 PNG 캡처. 원본과 독립적으로 만든 16:9 템플릿의 시각 요소를 비교한다. 이미지 합성/덮씌우기로 일치율을 조작해서는 안 된다. 원본과 수학적 픽셀 동일성은 목표로 약속하지 않으며, 텍스트/수치가 다른 디자인을 정량 점수 99%로 주장하기 전에 비교 기준·오차 마스크를 문서화해야 한다.

## 2. 엑셀/통계/차트 검증

**작은 정상 데이터셋:**

- XLSX 3시트 × 1,000~10,000행, 범주·숫자·음수·0·빈칸·텍스트·수식 캐시를 포함.
- 회사별 차트 색상이 자동으로 설정되는지 확인. 색상 변경이 계산값을 바꾸지 않아야 함.
- 데이터 3개(12, -5, 0)를 차트에 연결할 때 마이너스 막대·제로 기준선·레이블이 보존되는지 확인.
- 동일 데이터를 범주 집계 SUM, MEAN, MEDIAN, COUNT, HISTOGRAM, CUMULATIVE로 표시하여 Excel 값과 대조.
- 360개 연결 차트 항목이 중간 120개에서 잘리는지 확인.
- 도넛 차트는 음수 거부/양수·제로 허용; 12개 넘는 범주는 명확한 오류 안내.
- 빈 자료/근거 미입력은 숫자 `0`을 사실인 양 보고하지 않음.
- JSON/HTML 저장·재열기 후 값, 단위, 주석, 시트·범위 출처 대조.

**대용량 제한 게이트(별도):**

- 정확히 50 MiB XLSX 원본 파일, 압축 해제 256 MiB 이하.
- 통합문서 600,001셀 / 780,002셀 / 2,999,902셀 등 세 단계.
- 수식 캐시 포함 10,000개는 유지, 10,001개는 명시적으로 거부.
- 3,000,001셀 초과 파일은 부분 출력·묵시적 잘림 없이 거부.
- 브라우저 메모리·CPU·UI 일시 응답 중단 여부 기록.
- 대용량 결과는 선택된 차트/표만 프로젝트에 저장되고, 나머지 원본 분석은 XLSX 재업로드가 필요한 사실 안내 확인.
- Windows Chromium 및 Android Brave에서 같은 결과를 보여주는지 분리 검증. 모바일 저사양 기기는 50 MiB 지원이 보장되지 않는다.

## 3. UBS 특수 레퍼런스

- 16번 UBS는 기존 벡터 6쪽의 `source-ratio` 페이지. 이 프로젝트의 2025 원본 참고를 기반으로 제작됐으며 연구 목록의 2026 참고 링크와 연도가 다르다.
- SVG 압축 해제·지연 로드 완료 후 실제 6페이지 모두 보이는지 확인.
- 벡터 데이터 압축 해제 중 UBS 6페이지를 먼저 삽입한 경우, 로딩이 끝나면 빈 텍스트 슬롯이 생성되는지 확인. 새로고침/JSON 불러오기 후에도 사용자 입력값을 덮어쓰지 않고 빈 슬롯만 복구되는지 확인.
- 디자이너 벡터 레이어, 텍스트 빈칸 및 사용자 편집 블록이 충돌하거나 잘리는지 확인.
- UBS 페이지 13·16 연관 데이터 그래프 위치, 소스값 교체, HTML 재출력 검증.
- 과거 99% 숫자는 **원본 벡터 추출 도형 감사치**이지 편집기/브라우저 시각 동등성이나 수동 통과가 아님.

## 4. UX/출력·효과

- 모션 기본 OFF. 효과 89종 및 최대 3종 중첩을 사용자 선택 시 각 개별 실행해야 한다(별도 미완 게이트).
- 구석의 기능 상자 드래그 재배치 및 표준 UI 포커스/키보드/화면 크기 처리.
- 페이지별 내용 자동 구조화, 잠금, 차트/도형 분리, 로고 삽입 후 HTML 및 JSON에서 보존.
- 다크테마/우드테마 선택 시 레이아웃 좌표는 유지하고 색·대비만 변경.
- 모든 보고서 HTML을 로컬 파일로 열어 인터넷 없이 페이지 전환/차트/키보드 조작 확인.

## 5. 결과 보고 기록

각 테스트 실행 후 `companyId/pageIndex/testId`를 **PASS / FAIL / BLOCKED / NOT_RUN**으로 기록한다. 디자인 일치율은 실제 캡처 및 합의된 비교방법이 있어야만 숫자를 기록한다. `NOT_RUN`을 PASS로 표시하거나 배포 URL만으로 작업 완료라고 판단하지 않는다.

**현재 원칙:** 실기 검증과 배포를 강제로 시작하지 않는다. 사용자가 명시적으로 요청하면 당시 최신 Git SHA를 기준으로 1회 수동 배포하고 본 표를 집행한다.
