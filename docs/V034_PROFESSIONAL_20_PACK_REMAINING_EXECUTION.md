# DoCut 전문 보고서 20종 · 잔여 개발 실행계획 v2.0

**작성:** 2026-11-08 | **최신 저장소 기준선:** `c80cff99028b8cc0b713d432e8c242d534423541` (v0.33.0-development)  
**관련 자료:** [20종 공식 원본 분석](references/DoCut_Professional_Report_Reference20_Analysis.md), [20종 소스/메타](references/DoCut_Global_Professional_Reference20.json), [0.33 구현 사양](PROFESSIONAL_REFERENCE_PACKS_V033.md), [기존 통합 중간계획 v1.1](INTEGRATED_MIDTERM_PLAN_v1.1.md).

> **검증 경계:** 사용자 제공 20종 조사문에서 '120장은 권장 구현 목표'로 표기했지만, 현재 v0.33 저장소의 `assets/pro_reports.js`와 구현 사양은 **20개 독립 팩 × 6개 편집 페이지 = 120개 구조 코드가 포함됐다고 기록**한다. 신규 개발을 '처음 120개 생성'으로 중복 잡지 않는다. 코드를 넣은 사실과 원본 디자인 전문성/실제 사용자 기기 PASS는 별개의 지표이다.
>
> **제품 원칙:** DoCut은 PPT 호환 툴이 아닌 **편집 원본 JSON + 독립 실행형 16:9 HTML** 기반의 보고서·포스터 제작 스튜디오. 저작권 있는 원본 페이지/그래프/로고를 복사하지 않고 공개된 정보 구조를 재해석한다.

## 1. 최신 상태 기준표

| 항목 | 현재 관찰 | 인수 남은 것 |
|---|---|---|
| 공개 보고서 참조 | 20종 원본 링크와 5개 계열 등록 | PDF 직접 검토와 공식 인덱스 조회를 분리 표기, URL 존속성 |
| 편집 페이지 구성 | v0.33 소스 20×6=120개의 구조 생성 코드/갤러리 | **120/120 전수 편집·저장·재열기·HTML 출력** 및 서로 다른 구획의 시각 검증 |
| 기존 범용 페이지 키트 | 20개 legacy 별도 selector 유지 | 새 갤러리를 기본, 구 키트는 보조로 이관 |
| 레퍼런스 89 효과 | v0.32 코어/아이콘·퇴장 모드 설명 기록 | 개별 89개의 편집기·내보낸 HTML 실동작과 원본 출처 대조 |

| 데이터 모션 | XLSX/CSV 셀 범위·표/차트 코드 존재 | 연결 동작·값 보존·갱신 승인·숫자 형식 확인 |
| 독립 HTML | 저장·기본 런타임 있음 | 오프라인/시각·애니메이션 일치, 페이지 전환, JS 무실행 입력 |
| 전체 진척 | **미산정** | 최신 버전 실측 게이트 후만 산정 |

### 중요한 차이
- 템플릿 **갯수 충족**과 보고서 **전문성 충족**은 다르다. '배경색만 바뀐 4카드'는 실패로 간주.
- 120/120 코드를 이미 만들었다는 **구현 주장은 확인**, 그러나 120장 모두 원본과 비교된 100% 품질 통과는 증명되지 않았다.
- 공식 PDF에서 시각적으로 확인한 자료 vs IR 인덱스만 확인한 자료는 다른 증거 등급으로 관리.
- 사용자 고유 데이터는 생성한 템플릿의 임의 KPI/샘플 숫자로 대체하지 않는다.
- **ID 주의:** 연구 JSON/현재 코드에는 분기 실적 EARN-06/07/10/11/12, 연차 CORP-08/09/13으로 등록됐다. 사용자 서술의 06~10/11~13 연속 번호와 다르다. 기존 사용자 프로젝트가 참조할 수 있는 ID는 자동 재번호화하지 않고, 회사명·분류·원본 URL을 기준으로 대응표를 먼저 검증한다.

| 연차/ESG 3 | CORP-08~09·13 (Microsoft/Apple/Amazon) | 4차 | 경영자 서한·연간 목표·환경 성과·회계 주석 |

**오프라인·설치 아티팩트 관련:** 독립 HTML이 최종 산출물이며 자동 EXE/APK/ZIP·Actions·다수 중간 빌드를 만들지 않는다. PPTX를 주된 제품 목표/완료 게이트로 회귀시키지 않는다.

## 4. 120페이지 시각·기능 자동/수기 검증 표준

모든 `packId + pageIndex (0..5)`에 대해 아래 10개 점검 항목을 독립 기록한다.

| ID | 테스트 | 기계/실기 |
|---|---|---|
| R01 | 팩 고유 레이아웃/타이포 계층 구조, 타 19종과 구별 | 시각 + 구조 |
| R02 | 16:9 프레임 안의 제목/본문/주석/표/차트/페이지표시 | 정적 좌표 + 시각 |
| R03 | 사용자가 입력한 데이터 값·소수/단위·출처 유지 | 코드 |
| R04 | 박스 잠금·그룹·이동·크기 조절과 Undo/Redo | 코드 + 브라우저 |
| R05 | 장면 변경 때 편집·선택·입력 포커스/해시 탐색 보존 | 브라우저 |

| R08 | 보고서 기본 효과 OFF, 사용자 적용 89개 선택 시만 동작 | 브라우저 |
| R09 | 출처/이미지/로고 원본 무단 재배포 없음 | 자료 감사 |
| R10 | 390px/desktop/다크·인쇄 모드의 가독성과 내비게이션 | 실기 |

- 산출물: [120페이지 전수 인수 트래커](V034_REFERENCE_120_ACCEPTANCE_TRACKER.json) (20팩 × 6페이지 × R01~R10, **총 1,200개 NOT_RUN 기초 게이트**) + 대표 스크린샷/인수 체크. 실제 검증 실행 전에는 PASS를 쓰지 않는다. JSON의 `layoutCodePresent=true`는 실기 통과가 아니라 v0.33 코드 선언만 뜻한다.
- 각 팩은 6장 모두 PASS한 다음에만 '검수 완료' 레이블. 사용자 원본 회사의 공식 인증처럼 광고하지 않는다.

## 5. 실제 사용 목적별 자동 매핑

- **기승전결/결론형**: 논점·진단·원인·근거·선택지·실행.
- **분기 실적형**: 경영 요약·핵심 KPI·YoY·사업별 성과·전망·주석.
- **투자 전략형**: 전략축·목표 지표·성장 브리지·시나리오·자본투입·위험.
- **정책 위험형**: 현황·근거 수치·문제·2년/10년 비교·대안·조직 조치.
- 텍스트 붙여넣기/엑셀 입력 시 `title/claim/chart/table/note/source/action` 역할을 먼저 정하고 해당 의미 슬롯으로 배치한다.
- 16:9 변환은 글자만 줄이지 말고 초과 텍스트를 새 페이지로 분할 제안. 사용자 승인 전에는 콘텐츠를 덮어쓰지 않는다.

## 6. 운영 흐름·미완과 완료의 기록 규칙

1. **작업 시작:** 최신 Git tree/배포 버전/체크포인트 비교, 개인 프로젝트 JSON 백업.
2. **Phase 묶음:** 3팩 전문화(D1) → 실데이터 매핑(D2) → 20팩 검증(D3), 89효과·우클릭 병렬은 단일 묶음으로 회귀 테스트.
3. **CI:** 중간 CI 0, 최종 1회 수동 검증만. 소스는 충분한 작업 후 소수의 대형 커밋으로 업로드.
4. **완료율:** 코드 존재 개수와 실기 PASS 개수를 구분. '120 구조 존재'를 '원본 디자인 일치 100%'로 환산 금지.
5. **배포:** 명시적 수동 운영 배포 또는 사용자의 실기 검증 단계에 맞춰 1회 수행하고 운영 SHA/실기 증거 기록.

## 7. 인수 우선순위 한줄 결론

**새로운 레퍼런스 20개를 또 만드는 것보다, 이미 작성한 120장 중 맥킨지·BCG·BlackRock 18장을 전문 디자이너 수준으로 먼저 끌어올린 뒤, 120장 데이터 정확성과 독립 HTML 내보내기를 전수 인수하는 것이 빠르다.**

이 문서는 사용자가 제공한 20종 분석과 저장소 v0.33 코드의 차이를 반영한 **잔여 개발계획서**이다. 모델·라이선스·권리·실기 항목은 검사 전에 PASS 처리하지 않는다.
