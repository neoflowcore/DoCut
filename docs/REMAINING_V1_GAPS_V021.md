## V0.21 사용자 점검 흐름

1. 프로젝트 원본 JSON을 먼저 파일로 저장한다. 저장 충돌 또는 손상 경고가 있으면 복원·덮어쓰기 대신 안전한 로컬 백업부터 확보한다.
2. `콘텐츠 점검` 또는 `Ctrl+Shift+Q`를 사용해 현재와 권장 페이지 역할을 확인한다. 필터를 바꾸더라도 원본 문서의 수치, 기준일, 검증 표시가 변하지 않는지 확인한다.
3. 우선 확인 → 검토 필요 → 개선 제안 순으로 항목을 점검한다. 겹침 경고를 선택하면 양쪽 객체가 동시에 선택되어야 하며, 실제 의도된 겹침을 사람이 판정한다.
4. `점검 기록 TXT` 또는 `점검 내역 CSV`를 저장한다. Excel에서 CSV의 제목이 `=...`로 시작하는 경우 수식이 실행되지 않는지 확인한다. CSV 파일은 보고서 원자료가 아니라 자동 점검 내역이다.
5. 타사 HTML을 가져올 때 양쪽 프로젝트의 자동 경고 건수는 **독립적으로 계산**된 개수일 뿐 디자인/품질 점수와 전혀 무관함을 확인하고, 손실 경고 후 직접 승인한다.
6. AI 개선 요청 복사는 명시적 클릭으로만 이루어진다. 프로젝트 JSON은 자동으로 포함되지 않으며 입력한 원자료를 대체하지 않는다.

## 소스 검증 기록과 제외 범위

- `npm run check:syntax` PASS
- `npm test` PASS: **208/208 Node** (V0.21 신규 **36/36**)
- Chromium 10개 스위트 **분리 실행으로 141/141**: 14+11+12+15+14+13+16+12+15+19. 공통 실행이 동일 세션에서 중단 없이 통과했다는 주장과 구별한다.
- PPTX 메모리 구조 2종 PASS (기본 편집 개체·9종 통계차트); 실제 `.pptx` 산출물 생성/Office 열기 수행하지 않음.
- 정적 진단 부하 예시: 50페이지×120요소=6,000개에서 총 12,050개 권고 중 표시 1,200개·생략 10,850개, Node 소스 로컬 측정 **112ms**. 이는 고정 성능보장·실 사용자 기기 검증 수치가 아니다.
- 사용자 Windows/Android Brave 실제 브라우저, Microsoft PowerPoint, 89장 원본 디자인 정합률은 **미검증**.
- GitHub Actions 자동 실행, EXE·APK·ZIP, CI 배포·빌드, 신규 Vercel 서비스 배포는 **수행하지 않음**.

## 잔여 우선순위

첫째 원격 동기화 쓰기 권한을 해소하고 소스를 정확히 읽어 확인한다. 이후 사용자가 실기 요청하는 바로 직전에 한 번만 필요한 파일을 생성해 Windows/Android/Office 수기 검증을 시행한다. 자동 진단 결과의 0건, 기능 스위트의 전부 통과 또는 이전 42/53 비율을 **사용자 승인의 V1.0 출시 완성률**로 표현해서는 안 된다.
