# DoCut v0.45 — Excel 원본 전체 갱신·대용량 데이터 보존·HTML 출력 동기화

**기준:** `main` v0.44 `81aac4457017dc340930652396fa4505eab3704f`  
**목표:** 20종 전문 템플릿의 차트·표·KPI에 연결된 기존 엑셀 자료를 사용자가 다시 업로드하면, 모든 참조 객체를 **검토 후 원자적으로 갱신**한다. 사용자 입력으로 갱신을 선택하지 않으면 기존 자료는 변경되지 않는다.

## 2. 사용자 작업 흐름

1. 기존 프로젝트를 열고 **데이터 → 모션 차트·표**를 실행한다.
2. **기존 자료 전체 갱신 대상**에서 교체할 자료를 선택한다. *선택하지 않으면 기존 연결은 건드리지 않는다.*
3. 새 XLSX/CSV 파일을 업로드한다. 앱은 기존 자료 ID를 유지하며 새 파일의 시트 이름과 연결 범위를 대조한다.
4. 작업 유형 **기존 자료 교체 · 모든 연결 시각화 갱신**을 선택하거나 업로드 후 자동 선택된 값을 유지한다.
5. **검토**를 누르면 잠금 상태·원본 시트/범위·숫자·최대 포인트·참조 ID를 확인하고 모든 차트·표·지표의 새 값을 계산한다. 이상이 있으면 아무것도 변경하지 않는다.
6. **적용**을 누르면 안전 백업을 확보하고, 한 번의 Undo 체크포인트에 모든 갱신 결과를 반영한다.
7. 차트와 표를 선택하여 값·출처를 확인한 뒤 HTML/TXT 보고서를 내보낸다.

## 3. 일반 자료와 대용량 자료

- **원본 5,000셀 이하:** 전체 워크북 셀을 프로젝트의 기존 자료 ID로 교체하고, 연결된 모든 표·차트·KPI를 최신 값으로 계산한다.
- **5,000셀 초과:** 원본 파일은 브라우저에서 분석한다. 최대 30개의 연결 객체마다 별도 파생 시트를 만들어 **선택된 결과만 저장**한다. 원본의 관련 없는 셀과 수식은 포함되지 않는다.
- 시트 이름이 다르면 자동으로 다른 시트에 연결하지 않는다. 시트 순서/ID가 바뀌더라도 **이름이 정확히 일치하면** 매핑한다. 이름 변경 시 사용자가 개별 재연결해야 한다.
- 기존 저장 데이터가 이미 대용량 파생 결과 스냅샷이라면 원본 수식·시트 관계를 복원할 수 없으므로 **자동 일괄 갱신을 거부**한다. 새 파일을 업로드해 개별 차트를 다시 연결해야 한다.
- 연결 원본의 **새로운 행은 기존 참조 범위를 자동 확장하지 않는다**. 검토 메시지에서 추가 행이 기존 범위 밖일 수 있음을 알린다.
- 잠긴 연결 객체, 부적합 숫자, 결측·수식 캐시 누락, 범위 미존재, 30개 초과 연결 대용량 파일, 갱신 직전 객체 ID 변경은 **전체 적용 거부** 처리한다.
- 수식은 기존 정책에 따라 최대 10,000개/캐시 우선/허용된 수식만 계산하며, 원본 Excel 함수를 무제한 평가하지 않는다.
- **파일 한도 유지:** XLSX 압축 50 MiB, 압축 해제 256 MiB, 전체 최대 3,000,000셀·30,000행·256열. 기기 메모리에 따른 실시간 처리 성능은 별도 검증.

## 5. 수기 검증이 필요할 때(현재는 보류)

**수기검증 시작 시 최신 커밋을 Vercel/Cloudflare 운영 주소에 정확히 반영한 후에만** 다음 검증을 진행한다.

- 20종 × 6페이지 전수 로드, 빈 페이지·갤러리 미리보기·폰트/차트 누락 확인.
- 기존 엑셀 3장, 새 파일 3장으로 같은 자료 ID의 막대·선·표·KPI를 **동시 갱신**. 기존/신규 값과 Undo가 일치하는지 확인.
- 범위 누락·시트 이름 변경·잠금 객체·음수 도넛 등의 실패 시 자료 변경이 전혀 없는지 확인.
- 샘플 7,100셀, 780,002셀, 3백만 셀 한도 근접 파일을 차례로 검사. 작은 기기에서는 메모리 초과 가능성을 별도로 기록.
- 독립 HTML을 오프라인에서 재열어 최신 데이터·단위·출처·차트 반응이 유지되는지 확인.
- 기존 UBS 소스 6페이지 로딩이 끝나기 전/후 삽입을 실측하고 편집 데이터가 유지되는지 확인.
- 원본 기업 PDF와 레이아웃 비교는 **실측 디자인 지표를 따로 정의한 후** 수행. **99% 일치율을 미측정 상태에서 선언하지 않는다.**
