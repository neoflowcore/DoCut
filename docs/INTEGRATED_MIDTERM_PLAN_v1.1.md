# DoCut 통합 중간개발계획서 v1.1

**UI·UX · Effects · Web Design · Data Motion · Visual Scene**  
**기준일:** 2026-11-07 | **문서 성격:** 두 v1.0 계획서의 중복 제거·상호 충돌 해소·개발 Phase 일원화본

> **제품 정의** — DoCut은 웹사이트를 디자인하듯 보고서와 포스터를 제작하고, 탭·버튼·도형·차트·데이터·모션이 실제로 반응하는 **고정 출력 비율의 독립형 HTML**로 완성하는 시각 제작 스튜디오다. 콘텐츠 입력 → 디자인·구조 자동 구성 → 원하는 부분만 손보는 3단계 제작을 기본 경험으로 삼는다.

> **가장 중요한 제품 결정** — **PPT 호환은 목표가 아니다.** PPT가 하던 발표·시각 전달 작업을 **DoCut 고유의 웹 기술**로 대체하는 경험이 목표다. PPTX 읽기·쓰기·왕복 변환·오피스 객체 일치·PowerPoint용 애드인 개발은 이 계획에서 제외한다. 이미지·인쇄를 위한 정적 PNG/PDF는 선택적 출력이며, 핵심 산출물은 **작동하는 HTML**이다.

### 1.2 범위와 비범위

**포함:** 템플릿/레이아웃/효과 전수 구현, 웹페이지형 탭, 고정·사용자 비율, 브랜드/로고/폰트, Markdown·Marp식 구조 입력, 안전한 기존 HTML 불러오기, `.xlsx/.xls/.csv` 데이터 시각화, 차트·표 데이터 모션, AI 이미지·SVG·도형 레이어, 스마트 연결 화살표, 2.5D 광원·시차, 독립 HTML/JSON 저장, 선택적 정적 PNG·인쇄/PDF.

**의도적 제외:** PPTX 입출력 및 호환성, 전체 엑셀 애플리케이션 재구현, Excel 수식의 완전 재계산, 불특정 HTML의 모든 JS 자동 변환, 단일 비트맵의 모든 객체를 100% 완벽하게 분리한다는 보장, 본격적인 3D 메시 모델러, AI가 원본 데이터에 없는 수치를 만들어 차트에 넣는 기능.

### 1.3 하나의 문서, 하나의 요구 위치

- UX·비율·효과·출력·안전성은 **공통 장에 한 번만** 정의한다.
- Data Motion과 Visual Scene은 **각 엔진에 고유한 요구만** 기술한다.
- 원문별 중복 Phase는 없애고 **통합 P0~P10**으로 관리하며, DM/VS는 하위 작업 ID로 추적한다.
- 상위 v1.0의 ‘PPTX 후속 호환’ 표현은 소계획 v1.0의 최신 결정으로 **폐기**한다.

## 3. 사용자 경험·정보 구조

### 3.1 두 제품 화면

**DoCut Studio(편집기):** 프로젝트·소재 입력, 템플릿·효과·데이터·레이어 라이브러리, 실시간 캔버스, 컨텍스트 속성, 비교/Undo/버전, 내보내기.

**DoCut Report/Poster(배포물):** DoCut 편집 메뉴는 없으며, 사용자가 선택한 상단 탭/서브탭, 카드·데이터 차트·도형·화살표·모달·페이지 모션만 남는 결과물.

### 3.2 기본 3단계 — 제작 동선

```text
① 소재/내용 넣기
   ├─ 원문 텍스트·Markdown·표 붙여넣기
   ├─ Excel/CSV → 데이터 차트·KPI 추천
   ├─ ChatGPT 이미지/SVG/구조화 JSON → 포스터·장면 제안
   └─ 기존 HTML/프로젝트 JSON → 원본 보존·구조 분석
       ↓
② 목적별 템플릿 + 페이지 구조 + 추천 효과 선택
   └─ 클릭 전 실제 시각 미리보기·기존 콘텐츠 보존
       ↓
③ 필요한 카드·차트·이미지만 수정 → 탭·비율 확인 → HTML 저장
   └─ 정밀 제어는 고급 편집 모드에서 수행
```

- 빠른 제작 모드의 주 화면에는 전체 89목록/전문가 타임라인을 상시 펼치지 않는다.
- 객체 선택 시 **작은 인라인 도구막대**(효과/텍스트/색/배치/데이터/레이어)를 노출한다.
- 효과·차트·레이아웃 카드는 **그림으로 미리 이해할 수 있는 아이콘 + 실제 짧은 데모 + 적용** 구조로 통일한다.
- 처음 사용하는 사용자가 `내용 넣기 → 디자인 선택 → 저장`을 외부 개발 지식 없이 수행하는 것이 UX 합격선이다.

### 3.3 전문가 편집 모드

- 드래그, 크기 조절, 그룹, 스냅, 다중선택, 계층/Z순서, 정렬, 원형 로고, 8앵커 배치, 우클릭 잠금.
- 차트의 시트·범위·X/Y·집계·필터; 객체별 2.5D 깊이, 앵커·화살표 경로, 모션 지연·지속·이징·트리거·순서.
- 전체/컴포넌트 폰트, 배경/텍스트/보더/그림자 불투명도 분리, 키프레임·타임라인.
- 모든 편집은 Undo/Redo, 원본 대비 미리보기, 명시적인 적용/취소가 가능해야 한다.
- 인라인 텍스트 편집과 드래그/회전 제스처 충돌 방지. 터치에서는 hover를 탭/길게 누르기로 대체.

### 3.4 구조·탭 자동 제안

- 문서 목적(정책/실적/이사회/연구/포스터)과 내용의 `현황·문제·근거·비교·대안·결론`을 분석.
- 1/3/5/7/10 화면 등의 논리적 목차를 추천하되, 추천 제목을 사용자가 자유롭게 수정.
- 페이지 사이 이동, 상위 탭/하위 페이지 선택, 단축키, URL 해시 복원, 터치를 공통 상태 모델로 처리.

## 4. 고정 비율 웹 보고서와 내비게이션

### 4.1 보고서 계층

```text
ReportRoot
 ├─ Brand / Theme / Font
 ├─ OutputFrame (가로:세로비 고정, viewport에 맞춰 scale·letterbox)
 ├─ PrimaryTabs: WAIP | 사내대출 | 종합 결론 | ...
 │    └─ SubPages: 요약 | 외부 사례 | 대안 | 의견 | ...
 ├─ Scene: HTML/SVG/Chart/Table/Text/Image/Connector/Modal
 ├─ Animation + Interaction State
 └─ Export/Print UI (최종 HTML에 필요한 것만)
```

### 4.2 화면 비율 프리셋

| 프리셋 | 비율 | 표시/출력 조건 |
|---|---|---|
| 16:9(기본) | 1.777… | 전체화면 발표 |
| 4:3 | 1.333… | 일반 발표 |
| A4 가로 | 297:210 | 인쇄용 mm와 화면용 px 개념 구분 |
| A4 세로 | 210:297 | 안내문·포스터·세로 정책 보고서 |
| 9:16 | 0.5625 | 세로 발표·모바일 브리핑 |
| 사용자 지정 | `width:height` | 두 입력값 검증 후 미리보기·저장 |

- 상단 오른쪽 **작은 프레임 아이콘**으로 비율 선택. 사용자가 크기 옵션을 찾는 데 큰 패널을 거치지 않음.
- 탭·서브페이지·차트 필터·모달을 조작해도 **프레임 비율은 절대 변하지 않는다.** 창이 작으면 비율 유지 축소 또는 레터박스 처리.
- 사용자가 **비율 자체를 변경**하면 내부 의미 슬롯·그리드·앵커·커넥터가 재배치되며, 내용과 엑셀 원본값은 변하지 않음.
- 기본 발표는 **화면 바깥 스크롤 없이** 표시. 내용 과밀 시 간격 축소 → 슬롯 재배치 → 다른 레이아웃 → 분할 페이지를 제안; 원문·데이터 자동 삭제/최소 가독 크기 이하 축소 금지.
- 긴 표/상세 근거는 모달·선택적 내부 스크롤을 사용할 수 있으나, 발표 프레임 전체가 세로 스크롤되는 방식을 기본값으로 삼지 않음.
- 인쇄 시 페이지 단위 비율·여백·헤더/푸터를 검증하며, 포스터는 정지 이미지에서도 의미가 전달되도록 별도 프린트 상태 제공.

### 4.3 반응형/입력

- 편집기는 작은 화면에서 왼쪽/오른쪽 패널을 접고 하단 시트/모달 사용.
- 결과물은 **고정 비율 스케일 모드**가 기본; 필요한 경우 사용자 선택의 모바일 전용 뷰 제공.
- hover 효과는 키보드 포커스와 터치에서도 의미를 이해할 수 있는 대안 제공.
- 모션 감소 설정, 확대, 접근성 라벨·포커스 순서를 지원.

## 6. 의미 기반 레이아웃 엔진

### 6.1 현재 실패 유형(이전 코드 검토 기록)

- 일부 레이아웃은 요소 수가 슬롯 수보다 많으면 같은 공통 그리드로 되돌아가 결과가 비슷해짐.
- 요소의 **의미(title/claim/evidence/chart/source)**보다 배열 순서가 배치에 큰 영향을 미침.
- `콘텐츠 유지`/잠금/기존 좌표/자체 그룹·링크 연결 처리가 부족해 공간 겹침·유실 가능.
- A4 세로·사용자 비율에서 폰트 적합성/오버플로/분할 기준이 일관되지 않음.

### 6.2 비파괴 배치 파이프라인

```text
원본 콘텐츠/출처/데이터 Snapshot 고정
   ↓
노드 역할 분류(title, claim, evidence, metric, table, chart, image,
               formula, figure, quote, source, logo, connector, action)
   ↓
레이아웃 후보 선정: 6-card / 2-column / flow / KPI / poster / ...
   ↓
슬롯 매핑 + 잠금·그룹·앵커·연결·필요 최소 영역·출처 제약
   ↓
DOM/SVG/차트 실측 + 충돌·오버플로 감지
   ↓
여백 조정 → 카드 재배치 → 대체 구조 제안 → 추가 페이지 제안
   ↓
적용 전후 시각 비교 + 원문·데이터 diff → 사용자가 확정
   ↓
단일 Undo 트랜잭션 + Export 렌더링 검증
```

**필수:** 잠긴 제목/로고는 장애물로 간주하고 나머지를 그 주변에 배치. 슬롯 초과 시 카드 자동 삭제 금지. 실패는 ‘성공’이 아니라 **원인·대안·수정 가능 상태**를 제시. 비율 변경으로 데이터 계열/값이 달라져서는 안 됨.

**전수 적용 대상:** 기존 **12개 구조 버튼**, **9개 레이아웃 레퍼런스**, Pseudo-Lab 6패턴, KPI/차트/정책·의견·연구/포스터 구조. 각 구조의 고유 결과를 테스트하고 가짜 동일 레이아웃으로 대체하지 않음.

### 7.4 3중 효과 합성 엔진

- 한 객체 최대 3효과: `entrance + surface-light + pointer`처럼 **서로 독립적인 스타일·좌표·트리거 레이어**로 구성.

- **배경만 투명** 설정 시 글자·아이콘·테두리·효과 불변. 광원 좌표/색/반경/세기, 틸트 각도/지연 등 개별 조절.

- reduced-motion에서는 정보 손실 없이 정적 최종 상태/더 약한 표현 제공.

**항목별 DoD = 실동작 + 의미 일치 + 고유 아이콘 + 미리보기 + 편집/Undo + HTML 재생 + 키보드/터치/모션감소 검사 PASS.**

## 8. Data Motion: 엑셀 기반 모션 차트·표

> 이 장은 **실제 데이터와 시각 객체의 연결**에만 집중한다. 비율·효과·출력 규칙은 4·7·12장을 재사용한다.

### 8.1 입력·정규화·갱신

1. `.xlsx/.csv` 우선, `.xls`는 파서의 실제 지원/호환 테스트 후 활성화. **브라우저 로컬 파싱**을 기본값으로 둔다.
2. 시트 선택, 범위(`A1:E40`) 선택, 헤더행 여부, 숫자·기간·범주·텍스트·합계·결측·오류셀·수식 캐시·표시 서식 분석.
3. 데이터 정확성 경고: 숫자 속 통화 단위/퍼센트, 날짜 해석, 중복 헤더, 공백, `0`과 누락값, 반올림/큰 정수, 원본 수식 계산값의 신선도.
4. 정규화 스키마에 시트/범위/원본 식별자·해시, 열 역할, 단위·출처·시점, 데이터 스냅샷 저장.
5. 차트/KPI/표로 연결. 동일 파일 재불러오기 시 **변경 diff 표시 → 사용자 승인 → 매핑 유지 갱신**.
6. **매크로·엑셀 수식·외부 연결은 실행하지 않는다.** 재계산 결과를 임의로 만들어 내지 않는다. 암호화 파일과 캐시 부재에는 명확한 오류.
7. 독립 HTML에 넣는 데이터는 **내보낸 당시 스냅샷**이며 원본 Excel이 나중에 수정되어도 자동 반영된다고 표시하지 않는다.

| DM-3E | 워터폴·퍼널·게이지 | 누적·단계 모션 | 계산 근거·분모 확인 |

- **등장 효과**는 장식일 수 있어도 최종 표시 수치는 원본과 같아야 한다.
- **데이터 변경 효과**는 실제 이전값→신규값의 데이터 전환. 표시 텍스트·툴팁·축·차트는 같은 상태 참조.
- 표의 행을 선택하면 관련 차트와 KPI가 함께 강조되는 **연동 필터** 제공. 다른 페이지/탭과 연동 시 범위를 명시.
- 축/단위/출처/기준일/표시 소수점을 검사하고, AI로 없는 값을 메우거나 빈칸을 0으로 속이지 않는다.
- 큰 파일에서는 용량·행열수 경고, 가상 스크롤, 범위 기반 렌더/집계를 검토. 무제한 성능 약속 금지.

### 8.3 데이터 모션 편집 UX

## 9. Visual Scene: 2D·2.5D 포스터·다이어그램

> 이 장은 **독립적으로 편집 가능한 시각 레이어·스마트 연결·깊이감**에 집중한다. 효과 프리셋의 공통 엔진은 7장을 재사용한다.

### 9.1 소재 입력 3경로

1. **비트맵 이미지:** ChatGPT 생성 PNG/JPEG/WebP를 배경/피사체로 읽고, 제목·도형·화살표·차트는 별도 요소로 얹는다.
2. **SVG 벡터:** 경로·도형·아이콘·로고를 선택/그룹/편집 가능한 객체로 불러온다. 악성 SVG 이벤트·스크립트·외부 링크는 정제.
3. **구조화 JSON:** AI가 제안한 텍스트·레이어·색·위치·연결을 검증된 스키마로 입력하고 DoCut 객체로 생성한다.

**한계:** JPG/PNG 한 장에 합쳐진 모든 물체·문자를 100% 정확히 자동 분리한다고 주장하지 않는다. 이미지 위의 개별 편집 객체 추가를 기본으로 하고, 수동 마스크/선택적 AI 분리는 별도 확장으로 남긴다.

### 9.2 객체·레이어 모델

| 객체 | 필수 편집 속성 | 대표 동작 |
|---|---|---|
| 배경 | 색/그라데이션/사진/패턴/블러 | 시차·배경색 변화 |
| 이미지·피사체 | X/Y, 크기, 자르기, 마스크, 불투명도, Z | float·depth·tilt |
| SVG 도형 | 채움, 스트로크, 라운드, 회전, 그룹 | 선 그리기·회전·스케일 |
| 실제 텍스트 | 폰트·문단·부분서식·정렬 | typewriter·word-rise |
| 데이터 차트/표 | DataSource ID·시리즈·시점 | 8장 Data Motion 직접 연결 |
| 스마트 커넥터 | from/to ID, 앵커, 곡률, 레이어 | path draw·flowing light |
| 광원·강조 | 색/반경/세기/위치 | 커서 추적·ambient |
| 그룹·마스크 | 자식 요소·잠금·정렬·계층 | 그룹 진입/퇴장 |

### 9.3 스마트 화살표(장식 이미지가 아닌 연결 객체)

- `fromElementId → toElementId`를 저장하고, 시작·종료 앵커는 상/하/좌/우/중앙/사용자 좌표 지정.
- 객체 이동·크기 변경·그룹 이동·비율 변경 시 **앵커 및 화살표 경로 자동 재계산**.
- 직선/직각/베지어 곡선/점선/양방향, 화살촉 **6종 이상**, 두께/투명도/색/그라데이션/발광 선택.
- `path-draw`, 진행 점, 흐르는 광원, 순차 연결 등 실제 화살표에 맞는 애니메이션 제공.
- 충돌 회피는 기본 자동 경로로 시도하고, 실패할 경우 사용자가 웨이포인트 수동 조정.
- 기본 z-order는 본문 텍스트·데이터를 가리지 않도록 조정.

### 9.4 2.5D 구현 원칙

- 2D 좌표 X/Y + 깊이 Z + 카메라/포인터 시차 + 그림자·광원·원근을 결합한 **레이어 기반 시각 깊이**.
- 우선 기술: CSS `perspective/transform`, SVG 그림자·필터, CSS 변수 기반 포인터 추적. 실제 3D 메시 렌더링을 필수로 두지 않음.
- 프리셋: `floating-cards`, `layered-parallax`, `ambient-depth`, `cursor-tilt`, `depth-focus`, `stack-reveal`, `orbit-lite`, `edge-glow`.
- 광원·시차는 텍스트 가독성과 클릭 가능성을 손상시키면 안 됨. 3중 효과와 충돌 없이 함께 적용.
- 포인터가 없는 기기는 터치/정지 조명/드래그 방식으로 대체; 키보드 포커스에도 의미를 유지.
- 인쇄·reduced-motion 환경에서는 **의미가 보존된 정적 장면**을 기본 제공.

### 9.5 디지털·인쇄 포스터

- 공통 프로젝트 JSON에서 **움직이는 HTML 포스터**와 **정적인 PNG·인쇄/PDF**를 파생.
- 16:9·A4·세로·사용자 비율, 편집 px와 인쇄 mm를 구분.
- 텍스트를 비트맵 안에 박지 않고 실제 텍스트 객체로 유지하여 수정·검색·접근성을 확보.
- 템플릿과 포스터의 도형·화살표 연결도 프레임 비율 변경 시 유지.
- 외부 브랜드 이미지/논문 figure/폰트는 출처·권리 기록을 우선.

**Visual Scene 완료 기준:** 배경/이미지/SVG/텍스트/도형/차트/스마트 화살표를 따로 편집하고, 비율·위치 변경 후 연결을 유지하며 2.5D·3중 효과와 저장 HTML 재생이 일치함을 입증한다.

## 10. 입력·불러오기·AI/Markdown 구조화

### 10.1 공통 입력 라우터

| 원본 | 추출/제안 | 실패 시 보호 장치 |
|---|---|---|
| 텍스트·Markdown·Marp식 구문 | 제목/목차/페이지/표/수식/이미지 매핑 | 원문 보존, 변환 제안 비교 |
| Excel/CSV | 8장 Data Motion 데이터 스냅샷 | 수치·시트 범위·단위 경고 |
| PNG/JPEG/WebP/SVG/AI JSON | 9장 Visual Scene 레이어 | 원본 이미지 보존, SVG/JSON 검증 |
| DoCut 프로젝트 JSON | 전체 편집 상태/데이터/효과 복원 | 스키마 버전 마이그레이션·백업 |
| 일반 HTML | 탭/카드/표/차트/텍스트/로고/스타일 추출 | 격리 프레임·미지원 요소 손실 보고 |

### 10.2 Markdown / Marp식 입력(출력은 HTML)

- `#`, `##`: 제목·섹션 / `---`: 화면 또는 섹션 경계(설정) / 목록: 카드·절차·비교 / 표: 편집 가능한 표 / 이미지: 이미지+범례 / `$` 수식: Formula 노드.
- frontmatter: `theme`, `paginate`, `header`, `footer`, 페이지별 배경 색상 등 **지원한 필드만** 인식·설명.
- 문서 흐름에 따라 ‘현황→쟁점→분석→비교→대안→결론’ 구조·탭 이름 추천. 원문 수치·출처의 임의 요약/교체 금지.
- Pseudo-Lab의 **Marp 구조화 방식만 참고**하며 Marp CLI 또는 PPT 생성은 산출 목표가 아님.

### 10.3 기존 HTML 가져오기 3모드

1. **보존:** 원본 HTML 전체를 비활성/격리된 읽기용 보관+미리보기. 원본 덮어쓰기 금지.
2. **추출:** 제목/상위·하위 탭/표/차트/이미지/로고/효과를 DoCut 편집 요소로 변환 가능한 만큼 추출.
3. **하이브리드:** 복잡한 JS·`iframe`·`srcdoc`·data URL 로고·차트는 안전한 영역에서 표시하고, 변환 가능 영역만 편집.

**골든 샘플 계약:** 사용자 제공 WAIP 3화면 + 사내대출 4화면 = **2개 상위 탭/총 7화면**. 수치·출처·표 셀·글자 크기 최대 30px·콘텐츠 편집/저장·광원/차트·탭을 **원본과 변환본 비교 리포트**로 대조. 변환 불가 기능은 사용자에게 명확히 표시.

### 10.4 AI 입력 안전 경계

- AI가 제안한 레이아웃·수치 설명·장면 JSON은 **신뢰하지 않는 입력**으로 취급하며 스키마, URL, 데이터 출처를 검증.
- 사용자 명시 선택 전 원본 Excel·보고서 데이터를 AI 서비스에 자동 전송하지 않음. 사용량/비용/전송 범위를 표시.
- AI 생성 내용과 원본 근거 데이터를 구분하고, 원본 값을 자동으로 덮어쓰지 않음.
- 불특정 HTML·SVG의 임의 스크립트·이벤트 속성·외부 리소스 로드를 편집기 권한에서 실행하지 않음.

## 12. 독립 HTML 런타임·내보내기

### 12.1 필수 산출물

| 산출물 | 목적 | 합격 기준 |
|---|---|---|
| **독립형 HTML** | 웹사이트형 발표·디지털 포스터 | 편집 패널 없음, 탭·차트·장면·화살표·효과 실행 |
| **프로젝트 JSON** | 프로젝트 재편집·버전 복원 | 원본 데이터·레이어·효과·앵커·출처 복원 |
| 정적 PNG / SVG | 미리보기·정적 시각 자산 | 가능한 요소에 대해 해상도·글꼴·출처 점검 |
| 인쇄/PDF | A4 등 선택 비율의 정적 보고서 | 인쇄 시 애니메이션 종료 상태가 읽히며 잘림 최소화 |

**PPTX 관련 산출물은 없다.** `HTML → PPTX`도 이 계획의 단계나 합격 기준에 포함하지 않는다.

### 12.2 출력 실행 조건

- 미리보기와 HTML에 **같은 코어 컴포넌트·효과 구현**을 재사용해 Editor↔Export 동등성을 확보.
- HTML은 저장 당시 데이터 스냅샷, 필수 CSS/JS 및 허용된 자산을 내장. 파일 크기 제한·미디어 라이선스 확인.
- 기본 오프라인 모드에서 **외부 네트워크 요청 0**을 목표로 검증. 사용자가 외부 링크/서비스를 명시한 경우 별도 표시.
- 보고서용 메뉴·탭은 남기되 **DoCut Studio 전용 조작 패널·개발 콘솔·내부 데이터 관리 버튼 제거**.
- 페이지 내 모달/필터/탭/차트/화살표/2.5D 효과가 Chrome 기반 Brave·Android에서 작동하고 포커스/터치에 대응.
- 인쇄 시 숨은 페이지·탭을 어떻게 분할/출력할지 명확히 선택 가능하게 함(현재 화면만/전체 페이지/주제별).

## 13. 기술 아키텍처·선택 기준

```text
                    ┌─ Text / Markdown / Marp-style ─┐
                    ├─ Excel / CSV ──────────────────┤
입력 어댑터 ────────┼─ Image / SVG / AI-JSON ────────┼──> 정규화 프로젝트 모델
                    └─ HTML / DoCut-JSON ────────────┘              │

                                                                             │

```

### 13.1 라이브러리 선택 원칙

| 영역 | 후보 | 채택 선행 조건 |

| Excel/CSV | SheetJS 또는 동급 로컬 파서 | `.xlsx/.csv` 실제 파일, `.xls` 호환, 포맷 정확성·라이선스 |

| 2D 편집 | HTML/CSS/SVG 우선, 필요 시 Konva | 드래그·크기·레이어·키보드·선명도 |

### 15.2 원본 데이터·파일 안전

- Excel 원본·HTML 원본·이미지/프로젝트 파일 **덮어쓰기 금지**, 작업 전 버전/백업 확보.
- Excel 매크로·외부 링크·수식 자동 실행 금지; 수식 캐시 값과 재계산 값 차이를 표시. 큰 정수·퍼센트·통화·날짜/시간대·0분모 등 수학적 오류에 경고.
- 잘못된 CSV가 스프레드시트에서 수식으로 실행되지 않도록 다운로드 시 CSV injection 보호.
- SVG/HTML/AI JSON에 대한 **허용 목록·스키마 검증·격리 실행**, 외부 리소스 자동 실행·불필요한 개인정보 전송 차단.
- 소스 주장·통계·외부 기관 사례는 사용자 문서의 콘텐츠이며 DoCut이 사실 검증했다고 표시하지 않음. 출처/기준일·검증 필요 플래그 유지.
- 라이브러리/폰트/이미지·로고·참고 사이트 디자인의 재사용 권리와 최종 HTML 번들 라이선스 점검.

### 15.3 사용성·성능·접근성

- UI 과밀 방지: 기본/고급 모드 분리, 선택 요소 속성만 노출. 버튼은 실제 동작이 확인되는 상태만 완료 표시.
- `prefers-reduced-motion`, 모션 재생/일시정지/속도, 애니메이션 종료 상태/초점 유지.
- 포인터 추적은 `requestAnimationFrame`과 CSS 변수로 조절, 비활성 탭·화면 밖 모션 일시정지 및 리스너 정리.
- 큰 Excel·다중 차트·다수 SVG 레이어는 파일/객체 수 경고, 시각적으로 동일한 낮은 성능 모드 제공.
- 성능 수치 목표(FPS/메모리/번들 크기)는 **기준 테스트 환경에서 프로파일링 후** 확정. 실측 없는 수치로 완료 판정 금지.

### 15.4 **실기검증은 별도 필수**

> **Windows/Android 실기 PASS는 자동 테스트 PASS와 별개다.** 실제 조작 기록이 없으면 `미검증`으로 남긴다.

- [ ] Android Brave: 터치·세로 프레임·모달·필터·2.5D 폴백·파일 저장·입력.
- [ ] A4 세로/가로 인쇄: 텍스트·표·도형·화살표 잘림, 정적 모션 종료 상태.

## 17. 최종 완료 정의 및 착수 순서

### 17.1 통합 Definition of Done

**진짜 완료**는 버튼·템플릿 이름·데모가 존재하는 상태가 아니라, 사용자가 데이터를 넣고 웹페이지형 보고서/포스터를 만든 다음 **다른 기기의 브라우저에서 독립 HTML로 열어도 동일하게 작동**하는 상태다.

- [ ] 원본 콘텐츠/출처를 훼손하지 않고 3단계로 보고서·포스터 제작/저장.
- [ ] 템플릿 20종이 색뿐 아니라 구조·상태·차트·페이지 구성에서 차별화됨.
- [ ] 89개 레퍼런스 모두 추적되며, **52 실행 효과·11 전환**의 실제 동작·고유 아이콘·미리보기·Export가 통과.
- [ ] 한 객체 3중 효과가 독립 재생하고 배경 투명도는 글씨를 흐리지 않음.
- [ ] 12 구조/9 레이아웃/6 HTML 참조 패턴에서 잠금·의미 슬롯·비율·출처 유지.
- [ ] 16:9/A4/직접 입력 등에서 상/하 탭이 바뀌어도 프레임의 지정 비율 유지.
- [ ] **서로 다른 Excel 2종**의 원본 수치/기간/단위와 KPI·표·차트 모션·연동 상태 일치.
- [ ] 포스터의 이미지·SVG·도형·텍스트·스마트 화살표를 개별 수정, 비율 변경 후 연결 유지.
- [ ] 2.5D/광원/마우스·터치 효과가 HTML과 같고 reduced-motion 정적 상태 의미 유지.
- [ ] 기존 WAIP·사내대출 2탭/7화면 HTML을 원본 보존형으로 가져오고 미지원 항목을 누락 없이 보고.
- [ ] 네트워크 없는 브라우저에서 독립 HTML 탭/차트/화살표/모달/모션 실행, JSON으로 다시 편집.
- [ ] Windows/Android 실기검증 결과를 자동검증과 구분해 기록.
- [ ] **PPTX 호환 관련 기능을 완료 기준에 넣지 않음.**

1. v0.28 소스·골든 HTML·89원본 manifest·GitHub 접근 상태를 **다시 확인**하고 숨은 구현 부재를 목록화.
