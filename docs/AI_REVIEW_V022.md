# DoCut V0.22 · AI 제안 정밀 비교 및 선택 반영

> 범위: 기존 V0.21 소스에 대한 **로컬 개발 기능**. 온라인 배포·원본 사실 검증·Windows/Android Brave 수기검증을 뜻하지 않는다.

## 문제 정의

기존 AI 브리지에는 페이지별 변경 합계와 일부 수치만 표시되었다. 한 페이지에서 AI가 제안한 제목만 적용하려 해도 같은 페이지의 표·원자료·출처까지 함께 바뀔 위험이 있었다. 잠긴 요소도 AI 승인 경로를 통과하면 해제·변경·삭제될 수 있었고, 정확히 어떤 근거 문구가 수정되는지 확인하기 어려웠다.

## 구현한 사용자 흐름

1. `내보내기 → AI 제안 JSON 비교·반영`에서 DoCut JSON을 붙여넣고 `변경안 분석`을 누른다. **기본 승인 항목은 0개**다. 자동 계산은 문서를 변경하지 않는다.
2. 페이지 아래 `요소 변경 내역 보기`를 펼쳐 요소별 *수정/추가/삭제/보호* 상태, ID·유형·본문 전후·서식/위치/모션/원자료 변화, 수치 전후, 출처·기준일·단위·근거 전후를 읽는다. 기본 목록은 22개씩 렌더링하며 다음 22개 버튼으로 **누락 없이 추가 표시**한다. 모든 항목을 펼치기 전에는 해당 페이지 전체 승인을 할 수 없다. `전체 본문·원자료 확인`은 HTML을 실행하지 않는 읽기 전용 텍스트 패널이다. 원자료 미리보기의 20,000자 상한은 명시되며 원본 JSON을 별도 확인한다.
3. 페이지 전체 체크박스 또는 해당 페이지 안의 **개별 요소 체크박스** 중 하나를 선택한다. 페이지 전체 선택 시 개별 승인을 해제·비활성화해 중복 승인하지 않는다. 설정(title/theme/master 등)도 **설정별로 따로** 변경 전후를 읽고 개별 체크한다. 특히 마스터 로고는 원본 data URI를 화면이나 TXT에 노출하지 않고 용량·존재만 표시한다.
4. 숫자 변경·기존에는 없던 새 수치 삽입·기존 수치 삭제가 선택되면 별도의 `원본 근거를 직접 대조했습니다` 체크가 필요하다. **페이지 제목·요약문과 보고서 공통 제목·푸터의 수치 변경**도 같은 규칙을 적용한다. 기존/신규 요소의 출처·기준일·단위·근거 변경 제안을 선택하면 별도의 `근거 변경 승인` 체크가 필요하다. **두 위험이 겹치면 둘 모두 승인**해야 한다. 선택한 항목 묶음(페이지·개별 요소·공통 설정)을 바꾸면 앞선 위험 확인 체크가 초기화된다.
5. 잠긴 요소의 본문·속성·레이어 순서는 보존한다. 잠긴 요소가 포함된 페이지 삭제는 차단한다. AI가 기존 요소를 숨기거나 잠그는 변경, 새 요소를 숨기거나 잠그는 변경도 **원본 편집기의 명시적 조작이 아니므로 무시**한다. 새 요소·수치의 `verified:true` 주장은 인정하지 않는다. 원문 변경 시 해당 `verified`는 해제된다. 빈 문자열로 제안한 기존 출처·근거는 명시적 승인이 있어도 덮어쓰지 않는다.
6. `AI 변경 검토 TXT` 버튼으로 페이지·요소 선택과 변경을 TXT로 보존한다. 원본 프로젝트 전체 JSON을 무단 출력하지 않고 길이가 긴 원문은 발췌만 포함한다.
7. 승인 직전에 원문이 수정되었거나 AI JSON 자체를 다시 고쳤다면 **적용을 중단하고 재분석**해야 한다. AI의 본문 `text`와 부분 서식(`richText`)이 다른 실제 문구를 표시하면 분석 단계에서 거절한다. 적용 전 로컬 백업이 저장소 부족으로 실패하면 적용을 보류한다. 이때 모달 안의 **원본 JSON 백업**을 눌러 직접 내려받은 뒤, 현재 문서가 변하지 않은 상태에서 동일 승인 작업을 재시도할 수 있다. 적용은 단일 편집 이력으로 Undo 가능하다.

## 안전 경계

- AI 생성 텍스트와 ID는 HTML 이스케이프하며, HTML/SVG/JS를 실행하지 않는다.
- AI는 수치·출처·원본 사실을 참이라고 검증할 수 없다. 별도 확인 체크는 **사용자의 검토 행위 확인**일 뿐 진위 보증이 아니다.
- 잠긴 레이어를 AI 승인으로 우회하지 않는다. 레이어의 z-order 인덱스도 원본 위치를 유지한다.
- 페이지 ID 일치가 없는 위치 기반 제안은 페이지 전체 승인만 허용하며 개별 요소 승인은 제외한다.
- 다른 페이지에서 변경한 요소는 원본 내용을 보존한다. 개별 승인 시 페이지 메타데이터(tab/background 등)는 변경하지 않는다.
- 초기 코드에 있던 AI의 `verified:true` 자기 주장을 실제 검증으로 승격시키지 않는다.
- 화면의 초기 렌더링은 변경 요소 **22개씩** 표시하며 추가 버튼으로 모두 펼칠 수 있다. 특히 22개 초과 페이지는 모든 항목을 펼치기 전까지 전체 페이지 승인이 잠긴다. 이 화면만으로 원본 화면 픽셀 동등성과 수치 진위는 판단할 수 없다.
- 데이터 손실을 일으킬 수 있는 일괄 변경의 사전 백업 규칙은 AI 제안뿐 아니라 **전체 찾기·바꾸기, CSV·TSV 반영, HTML/JSON 보고서 추가·교체**에도 적용한다. 로컬 백업이 불가능하고 동일한 현재 문서 JSON 다운로드도 없으면 변경하지 않는다.
- **다운로드한 JSON은 브라우저 자동 저장의 대체물이 아니다.** 파일이 실제 기기에 남았는지 사용자가 확인해야 하며, 사후 편집 내용은 이전에 다운로드한 파일에 소급 보존되지 않는다.

## 데이터 계약

- `DocutProposal.analyze(before, proposal)`는 후보와 각 페이지의 `review.items`를 반환한다. `originalSignature`는 적용 시 입력 원문 변화를 감지하기 위한 내부 스냅샷이다.
- `DocutProposal.apply(current,analysis,wholePages,settings,{elementSelection,settingSelection,approveNumeric,allowEvidenceChange})`는 승인된 대상만 변경한다. `elementSelection`은 분석 페이지 인덱스를 키로 하고 **요소 ID 배열**을 값으로 가진다. `settingSelection`은 변경된 공통 설정 중 실제 선택한 키만 포함한다.
- `.apply`는 존재하지 않거나 잠긴 요소, 불일치하는 페이지 ID, 기존 분석에 없던 선택, 한 페이지를 전체·개별 이중 승인하는 요청, 승인 누락 및 수정된 원문을 예외로 거부한다.
- `formatReview`는 페이지·개별 요소·공통 설정 선택과 변경 전후를 포함한 TXT 점검 기록을 생성한다. 이 TXT는 보고서 원문 보존용 JSON이 아니다.

## 실제 실기검증 전 경계

- Chromium 합성 저장소 환경에서 버튼·모달·다운로드·390px 배치를 검증한다. 이것은 실제 사용자 Windows/Android Brave 테스트가 아니다.
- Microsoft PowerPoint 파일을 새로 만들거나 실행하지 않았으며, PPTX 출력을 V0.22에서 변경하지 않았다.
- GitHub Actions, EXE/APK/ZIP 아티팩트, 새 배포를 만들지 않는다.
