# DoCut V0.21 · 근거 중심 보고서 품질 점검 · 스토리맵

> 범위: 설치 없는 로컬 소스 개발. 본 기능은 보고서 사실 확인·전문가 인증·디자인 원본 복제를 수행하지 않는다.
> 대상: `neoflowcore/DoCut`에서 복원된 V0.20 소스만. 타 프로젝트·외부 배포와 무관.

## 목적

DoCut 보고서 사용자는 16:9 화면에 내용·표·이미지·모션을 배치하고, 기승전결 또는 제도 분석·비교·대안·실행의 논리 구조를 갖춰야 한다. V0.20의 단순 `auditProject()`는 출처 누락·샘플 문구를 낱개 경고로만 보여줬다. V0.21은 작성자에게 **어디를, 무엇 때문에, 어떤 자료로 보완해야 하는지** 알려주되 콘텐츠·수치·근거를 자동 수정하지 않는다.

## 신규 로컬 모듈

`assets/quality_review.js`는 DOM·원격 서버·설치 패키지 없이 작동한다.

- `analyze(project)` → 페이지별 현재 제목, 추천 역할, 질문, 요소·출처·사용자 검증 표시·권고 건수. 경고는 `rule`, `severity`, `category`, `pageIndex`, `id`, `message`, `hint`를 가진다.
- `filter(result,severity,category)` → 두 필터의 교집합. `all`은 전체.
- `compare(current,candidate)` → **양쪽 프로젝트의 독립적인 자동 경고 건수**. 수치 차이가 품질 점수나 검증 결과라는 주장은 하지 않음.
- `formatTxt(result)` → 사람이 검토할 수 있는 TXT. 선택 개체 ID·위치·원인·가이드 및 기승전결 스토리맵.
- `aiChecklist(result)` → 구조/근거/표현 개선을 요청하는 텍스트. 원본 JSON을 숨겨서 내보내는 기능이 아니며, 원문 수치·기준일·출처·검증 표시의 임의 변경을 금지하도록 안내.

기존 C.auditProject는 하위 호환을 위해 유지한다. 기존 V0.15 근거 TXT의 행 기록은 보존하며, 자동 경고 부문은 신규 분류를 사용한다.

## 점검 항목 및 한계

| 범위 | 자동 확인 예시 | 자동 확인하지 않는 것 |
|---|---|---|
| 논리 구조 | 빈 페이지·큰 제목 누락·중복 탭·기존 안내/샘플 문구·긴 제목 | 주장 간 인과관계의 진실성과 정책 타당성 |
| 근거·수치 | 차트/표/KPI 출처·기준일·단위·직접 확인 표시, 미입력 통계행, 도넛 비중·표 구조, 본문에 언급된 일부 % | 원자료의 신뢰성·통계 방법론의 과학적 검증·숨겨진 수치 오류 |
| 16:9 레이아웃 | 유효한 위치·크기, 화면 바깥 요소, 내용 요소 간 큰 겹침, 텍스트 밀도 추정 | 브라우저/폰트별 픽셀 단위 넘침·모든 의도적 겹침 구분 |
| 접근성 | 직접 지정된 단색 글자/배경의 대비, 이미지 원본·대체 설명 | 그라디언트·투명 배경의 최종 대비, 실제 스크린리더 테스트 |
| 모션 | 3효과 상한, 총 재생 지연 과다 | GPU 성능과 프레임률의 실기 측정 |

우선순위는 **우선 확인 / 검토 필요 / 개선 제안**으로 표시한다. 경고는 문서 사실 오류가 아니라 자동 휴리스틱이다. 위험 항목이 0건이어도 검증 완료를 의미하지 않는다. 입력 데이터는 변경하지 않는다. 보고서 전체 완성률(%)을 계산하지 않으며 사용자의 기존 인수 기준 42/53과도 별개이다.

제어를 벗어나는 복잡한 보고서에서도 응답하도록 렌더링 목록은 최대 1,200건으로 제한하고, 초과 건수와 전체 합계는 별도 보존한다. 문서의 페이지별 실제 권고 총계는 제한 건수를 포함한다.

## 사용자 인터페이스

1. 상단 **콘텐츠 점검** 또는 `Ctrl+Shift+Q`로 열기. 원본 문서가 자동 수정되지 않는다.
2. 5종 스토리모드에 맞춰 현재 탭 제목·권장 역할·검토 질문(예: 외부 사례의 작용/부작용)을 보여준다. 원래 사용자 지정 탭은 덮어쓰지 않는다.
3. 심각도와 분야 필터를 조합해 점검. 항목을 누르면 해당 페이지·요소로 이동.
4. 직접 누를 때만 `점검 기록 TXT 저장`, `AI 개선 요청 복사`. 브라우저 밖 자동 전송·클라우드 연동 없음.
5. HTML 가져오기 검토에도 **현재 문서와 정적 변환 후보 각각의 자동 경고 수**를 표시. 이는 원본 HTML의 픽셀 차이 검증이나 변경 후 최종 보고서 승인 결과가 아니다. 가져오기 체크/확인은 V0.20의 명시적 동의를 유지한다.
6. 기존 AI 제작 프롬프트에 기승전결 질문 및 상위 45개 자동 경고를 포함. AI가 자의로 수치·근거·검증 상태를 편집해서는 안 된다는 지침을 유지한다.

## 회귀 검증과 향후 실기 체크

- Node 신규 순수 로직 검사: `node --test tests/quality_review_v021.test.cjs`.
- Chromium UI 검사: `python tests/browser_v021.py` (synthetic storage and injected local files; Windows/Android Brave 실기 검증 아님).
- 기존 전체: `npm run check:syntax`, `npm test`, V0.13~V0.20 브라우저 suite 및 PPTX 메모리 구조 suite. `tools/check_source_v021.sh`를 **개발 종료 후 1회 수동 실행**한다. 테스트는 소스 코드 실행뿐이며 배포·설치파일을 생성하지 않는다.
- Windows Brave 확인: 1500px+ / 390px UI, 키보드 Ctrl+Shift+Q, 경고 검색, 모바일 스크롤, 항목 클릭 위치, TXT다운로드, JSON 재열기, 복사 결과 확인.
- 실제 수치/출처 대조: 근거 입력 후 사용자 확인 표시가 남는지, 수치 변경 시 표시가 해제되는지, 파일 인용·기준일이 정확한지 수작업으로 검사.
- 외부 HTML: 변환 후보의 자동 경고가 원본 HTML과의 픽셀 동일성으로 오해되지 않는지 화면에서 확인.
- 실제 Android Brave, Microsoft PowerPoint, 원본 89장 이미지 시안의 정량적 시각 비교는 수행 전이다.

## 운영

프로젝트 소스만 저장/커밋한다. GitHub Actions `on: push` 워크플로 추가 금지, CI 빌드·설치 EXE/APK/ZIP 생성 금지. GitHub 저장소는 사용자가 이미 지정한 `neoflowcore/DoCut` 외에는 접근하지 않는다. GitHub 쓰기 권한이 403이면 원격 성공 주장을 하지 않고 전체 소스 Git-format TXT 패치 및 검증 기록을 프로젝트 Library `/DoCut`에 보존한다.

## 추가 검토 안전장치

- 잘못된 `pageIndex` 또는 문서에 없는 요소 ID를 가리키는 점검 항목 클릭은 문서 선택을 변조하지 않는다.
- 내용 요소 두 개가 겹칠 때 양쪽 요소 ID를 보고서 TXT에 함께 기록하고, 해당 페이지에서 두 요소를 동시에 강조한다. 두 요소의 의도된 겹침인지는 사용자 판정이다.
- 서로 다른 페이지에 동일 요소 ID가 존재하는 손상된 프로젝트는 문서를 직접 변경하지 않고 `DUPLICATE_GLOBAL_ID` 검토 문제로 안내한다.
- 막대·선·도넛 차트에서 범주 레이블 중복(대소문자 무시), 도넛의 전부 0인 수치 배열을 확인한다. 데이터 값은 추측해서 채우지 않는다.
- 페이지에서 상대적으로 고비용인 효과를 사용하는 요소가 5개를 넘으면 성능 점검을 제안한다. 이 숫자는 FPS나 GPU 부하 측정값이 아니라 소스 구성의 정적 분류이다.

## CSV 경고 목록 내보내기

수기 점검 및 Excel 기반 의견 수렴을 위해 `점검 내역 CSV 저장`을 제공한다. 기본 CSV에는 페이지, 페이지 제목, 우선순위, 분류, 진단 규칙, 두 겹침 요소 ID, 안내 문구가 포함된다. Excel 호환 UTF-8 BOM과 CRLF 행 구분을 사용하며, 사용자 입력 제목이 `=`, `+`, `-`, `@` 등으로 시작하면 수식으로 실행되지 않도록 값 앞에 작은따옴표를 붙인다. 이 파일은 원본 보고서의 데이터 출처가 아니며 **자동 점검 항목 목록**이다.
