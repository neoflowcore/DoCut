## 1. 사용자 요구사항 · 우선순위 고정

**핵심 UX 원칙: `작업은 단순하게, 결과는 고도화되게`.** 초보자는 콘텐츠·디자인·검증·재생을 쉽게 찾고 고급 사용자는 상세 요소/모션 도구에 접근.

### P0 선행: 이 문서와 기준선 고정
1. 실재하는 로컬 패치/기능/원격 권한/레퍼런스 인덱스를 구분.
2. 변동 사항·실패 검사·임시 해결을 기록하고 최종 커밋은 1개로 묶음.

### P1 최우선: 상단 `[검증]` 버튼 (기존 `콘텐츠 점검` **바로 왼쪽**)
1. 오른쪽 속성/요소 작업 패널 내부에서 3개 탭: **① 오탈자 ② 보고서 문제 ③ AI 문장 개선 중심**.
2. 오탈자: 보수적인 로컬 한·영 철자/중복/공백 후보; 한글 IME 입력 중 검사 금지. 전체/현재 페이지/선택 요소 범위, 개별 변경 전후 확인·Undo, 전문용어 오탐 피하기. 로컬 규칙은 완전한 한국어 형태소 교정이 아님.
3. 보고서 문제: V0.21 `DocutQualityReview`의 논리, 근거·기준일·수치·배치·접근성 점검을 오른쪽에 표시하고 클릭 시 해당 페이지/요소로 이동; 원문 자동 변경 금지.
4. AI 문장 개선: 외부 AI 자동 호출 없음(인증/연동 불가). 선택 텍스트에 대한 **외부 AI 요청 프롬프트를 명시적으로 복사**하고 사용자가 별도 제공한 개선 문장을 원문/제안 비교 후 승인. 모델이 검증된 사실을 조작하거나 모든 문서를 자동 전송했다고 표시하지 않는다.
5. AI/오탈자 적용 시 잠금·원본 변경 중단·부분서식 충돌·숫자/단위/출처 보호·로컬 백업/Undo를 우선. 출처, 검증표시, chart/table 원자료는 건드리지 않음.

### P2: 좌측 페이지/요소 · 우측 속성/검증 패널 조절
1. 두 경계에 **1px 투명 글라스 헤어라인 + 드래그 핸들**. 포인터/터치/키보드 조작, 창 폭 제한, 재배치 후 캔버스 맞춤 자동 계산.
2. 저장은 프로젝트 JSON 아닌 UI 디바이스 설정이며, 저장소 충돌/불가 시 메모리 기본값으로 폴백.
3. 모바일 ≤640px에서는 기존 슬라이드/오버레이 탐색을 유지하고 데스크톱 드래그 경계는 숨김. 닫기·접근성에 영향 없음.

### P3: 디자인 프리셋 간소화 및 고도화
1. 기존 10종 페이지 키트/9개 팔레트/12개 레이아웃/28개 효과 스택은 보존. 대표 패턴 검색·추천·빠른 적용, 기존 문서 덮어쓰기 금지, 변경 내용 미리보기·Undo.
2. 요약된 상위 진입점 + 상세 도구 접기. 같은 기능의 중복 버튼을 늘리지 않는다.

### P4: 페이지 전환과 89장 효과 레퍼런스
1. 보유한 `effect_reference_catalog(2).json`은 89장 **파일명·그룹·설명 메타데이터**이고 원본 사진·영상은 현재 소스 폴더에 없음. 프로젝트의 이전 분석 MD는 원본 ZIP을 89장으로 분류한 기록을 제공함. **실물 89장 이미지의 픽셀 일치율은 평가 불가**.
2. JPEG 89장이 효과 89개라는 주장은 거짓. 분류에는 차트2, 인터랙션 모음35, 랜딩 모션18, 14기초 모션4, 컬러9, 대시보드4, 타이포/UX/기타가 포함됨. 이미지별 실제 프레임·속도·easing은 알 수 없다.
3. 이미 존재하는 요소별 최대 3효과/페이지 전환 5개(`none`, `fade`, `slide`, `zoom`, `wipe`)를 페이지 전환 확대, 미리보기·HTML 재생 일치, `prefers-reduced-motion`, 16:9 무스크롤 규칙 아래 재구성.
4. 레퍼런스 ID ↔ 구현 효과/색/레이아웃 매핑 MD+데이터에 **구현됨 / 부분 지원 / 미구현 / 이미지 미검증** 상태 명시. 라이선스 소유 불명인 스크린샷 자체는 앱에 번들하지 않는다.

## 2. 변경 불변식과 합격 기준

- 코드 변경 시 16:9·50페이지 상한·100요소 상한·저장 백업·Undo, 공개 HTML과 내부 리뷰 분리 유지.
- 자동 점검은 **출처 진위나 한국어 문법에 대한 공식 보증이 아님**.
- 저장 전 백업 실패하면 고위험 일괄 수정 보류; 편집중인 IME를 rerender로 끊지 않음.
- 개인 검토 정보는 외부 AI로 묵시 전송 금지.
- 테스트는 신규 모듈/브라우저 흐름 및 기존 주요 회귀 검사 완료 후 한꺼번에 실행. 실패 수치는 실패로 기록.
- GitHub 쓰기 오류가 재현되면 원격 업로드 미완료와 권한 회복 경로를 명시. Actions/CI 자동 실행, EXE/APK/ZIP, 실제 PPTX/배포 생성 금지.
