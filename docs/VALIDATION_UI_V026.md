# DoCut V0.26 — [검증] 센터 · 글라스 작업 패널 · 디자인/전환 고도화

기준일: 2026-11-05 | 범위: 소스 구현 + 합성 Chromium 자동검사 | 출시/실기검증: 아직 하지 않음

## 1. 사용자 화면에 적용한 방식

- 상단 `✓ 검증`은 `⚑ 콘텐츠 점검` **바로 왼쪽**에 배치한다. 기존 콘텐츠 점검 창, 내부 검토 메모 및 사용자의 데이터 모델은 삭제하지 않는다.
- 클릭하면 기존 오른쪽 **요소 작업 패널을 교체**하는 3모드 검증 센터가 열린다. 별도 팝업·새 탭을 열지 않아 작업 흐름이 단순하다.
- ① **오탈자**: 전체/현재 페이지/선택 요소, 한국어/영어/혼합. 정규식 기반의 명백한 오탈자·공백·단어 반복 후보를 한 건씩 제안한다. 위치 이동, 개별 승인, Undo를 제공한다. 80건씩 추가 표시한다. 실시간 한국어 형태소/띄어쓰기 전체 교정, 온라인 사전 검색, 공식 국립국어원 판정은 아직 지원하지 않는다.
- ② **보고서 문제**: 기존 `DocutQualityReview`의 논리·근거·기준일·단위·통계 입력·레이아웃 충돌·가독성/접근성·모션 경고를 읽기 전용으로 보여준다. 해당 페이지/요소(겹침 문제의 상대 요소 포함)로 이동하고 선택 범위로 필터링한다. 근거의 사실 진위나 표본·법령 적합성을 자동 확정하지 않는다.
- ③ **AI 문장 개선**: 별도 AI API/인증 연동 없이, 사용자가 선택한 **일반 텍스트 요소 한 개**를 바탕으로 프롬프트를 *명시적으로* 클립보드에 복사한다. AI 또는 사람이 작성한 제안문을 붙여넣어 차이를 비교한 뒤 사용자가 `검토한 문장만 적용`을 눌러야 반영된다. 문서 전체 전송·자동 교정이라고 주장하지 않는다.

## 2. 수정 보호 경계

- 표·차트·통계 원자료, 출처/각주, 잠김·숨김·부분서식 요소는 V0.26 일반 텍스트 자동 후보 대상에서 제외한다.
- 원문을 읽은 뒤 바뀐 요소는 편집을 거부하며, 숫자/단위/기준일의 값 배열이 달라지는 경우도 승인 전에 중단한다. 선택한 요소 텍스트만 변경하며 `verified`를 해제한다. 별도 `source`, 표·차트 `data`, 내부 리뷰 기록은 수정하지 않는다.
- 기존 `preMutationBackup()`의 성공 또는 동등한 JSON 작업본 백업이 없으면 수정 적용을 보류한다. 단일 Undo 체크포인트와 기존 자동 저장 충돌 보호가 유지된다.
- 캔버스 IME 조합 중에 문서 전체를 실시간 분석하거나 편집 영역을 재구성하지 않는다. 검증은 별도 패널에서 검사하는 *수동 흐름*이다.
- 한국어 규칙은 오류 가능성이 있는 완전한 자동 교정이 아니다. 문맥·의미·법령 인용과 모든 단위의 정확성을 사용자가 최종 확인해야 한다.

## 3. 자유 조절 글라스 경계

- 좌측 `구성/요소/디자인` 패널과 중앙 캔버스, 중앙과 오른쪽 `요소 작업/검증` 사이에 **약 1px 반투명 글라스 선 + 10px 투명 포인터 영역**을 둔다.
- 좌·우 폭 조절은 포인터 드래그, 키보드 ←/→, Shift+방향키(빠른 이동), Home/End, 더블클릭 초기화로 수행한다. ARIA separator 값·한계가 갱신된다.
- 좌측 178–550px, 우측 230–590px을 기준으로 가운데 캔버스 영역 300px을 남기려 시도하며, 줄어든 뷰포트에서는 최소폭을 우선한다. 너비는 브라우저의 `docut-ui-pane-widths-v026`에만 저장하며 보고서 JSON으로 내보내지 않는다.
- 모바일 ≤880px에서는 기존 반응형 오버레이를 사용하고 데스크톱 분할 조절선은 숨긴다.

## 4. `작업은 단순하게, 결과는 고도화되게` 디자인 동선

- 왼쪽 `디자인` 첫 진입점은 **보고서 기본 / 우드 브라운 / 앰비언트** 3개. 기존 9종 팔레트는 펼쳐 보기로 유지.
- 현재 페이지의 **장면 전환 11종**은 드롭다운 선택→적용, 필요 시 별도 한 번 미리보기. 편집기의 미리보기와 단일 HTML의 전환에 동일 `assets/page_transitions.js`의 정의를 적용한다.
- 기존 요소별 최대 3효과, 10종 페이지 키트, 9개 팔레트, 12 레이아웃, 타임라인 및 28 효과 종류는 유지한다. 이번 작업이 이 모든 기능을 새로 구현한 것은 아니다.
- 기존 89장 레퍼런스 분석의 파일명·설명을 **16개 카테고리 / 89개 개별 항목**으로 재매핑했다(`assets/reference_map.js`, `REFERENCE_89_MAPPING_V026.md`). 52개는 기존 요소 프리셋 계열, 11개는 팔레트, 11개는 페이지 전환, 9개는 레이아웃에 연결했고 6개는 실행 없는 UX/방법론 참고로 유지했다. 이는 **메타데이터 매핑**이며 89개 효과/89개 원본 영상 구현이 아니다.
- 89개 중 구현 계열에 대한 *개략적* 대응 39개, 원본 키프레임·형태 미대조 42개, 중복 시안 2개, 실행 없는 참고 6개. 원본 JPEG 실제 바이트와 영상은 현재 소스에 없으므로 픽셀 정합률/원본 프레임·속도 일치율을 **산정하지 않는다**.
- 레퍼런스는 상세 펼침 영역에 넣어 기본 UX를 복잡하게 만들지 않는다. 각 `적용` 버튼은 권한/현재 요소 유형에 따라 실제 기존 효과·테마·레이아웃에 연결하거나 설명을 표시하고, 원본 사진을 제품에 재배포하지 않는다.

## 5. 검사와 남은 작업

- 정적 문법과 Node 자동검사, 합성 Chromium (데스크톱/390px), 단일 HTML의 오프라인 실행, PPTX **메모리 내** 구조 검사를 소스 개발 검증으로 사용한다. 실 사용자 기기 또는 Office 앱 테스트를 PASS로 세지 않는다.
- 원본 레퍼런스 89장과 제품의 정확한 시각 비교, 한국어 문맥·띄어쓰기 고급 검사 엔진, 외부 AI 정식 사용자 선택형 연결, UI 기기별 폰트·GPU 성능, 16:9 화면 사용성, 실제 Windows/Android Brave, Microsoft PowerPoint 편집·재저장, GitHub App 접근 복구 및 원격 동기화는 별도 잔여 항목이다.
- 원격 GitHub 저장소는 비어 있으며 이전 API 쓰기 403, 기존 Vercel 운영 사이트는 V0.15.0. 버전 차이를 사용자에게 명확히 고지한다.
- Actions/CI·설치 빌드·EXE/APK/ZIP·실제 PPTX/신규 배포를 이 개발 단계에서 시작하지 않는다.

## V0.26 연결 해제 후 사용성·보호 추가

- 페이지 탭 제목/헤드라인/설명도 로컬 오탈자 후보에 포함. 페이지의 기존 제목만 바꾸고 다른 블록·출처는 수정하지 않는다.
- 인용 라벨 `출처`, `자료 출처`, `참고 자료`, `근거`, `Source`, `Reference`와 그 인용 문자열, 외부 URL·이메일 주소는 교정 AI가 의미를 임의 바꾸지 못하도록 보수적으로 보호. 본문 속 모든 법적 사실을 자동 검증한다는 뜻은 아니다.
- 오탐 `무시`는 **메모리 세션 전용**이며 잘못 무시한 항목은 `이번 세션 무시 항목 다시 표시`로 복구. 사용자 사전의 브라우저 영구 저장이나 외부 전송은 하지 않음.
- 이미지 자료는 없는 상태지만 89개 **파일명·설명**을 검색할 수 있으며 01–89 번호로 표시한다. 모션·타이포 등 그룹을 펼쳐 기존 구현 프리셋에 연결하는 수준.
- 전체 QA 집계: Node 446/446; Chromium 302/302(분할); PPTX 메모리 2/2. 실제 Windows/Android Brave, Office 수기검증은 미실시.
