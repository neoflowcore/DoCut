# DoCut v0.47 — Excel 지표 의미 검증·차트별 수동 열 지정·데이터 출처 보존

> **범위:** 20개 전문 보고서 레퍼런스 중 19개 네이티브 독립 디자인 계열의 기존 6페이지 차트 슬롯 데이터 연결. 16번 UBS는 source-ratio SVG 벡터 시범 경로를 유지한다.
> **배포/실기 상태:** 소스 개발 단계. Vercel 수동 배포, 실브라우저 수기검증, GitHub Actions, EXE/APK/ZIP 생성 없음. 원본 PDF 대비 디자인 일치율은 미측정.

## 1. 확인된 문제

v0.46 자동 데이터 매핑은 **차트 슬롯 하나 + 숫자 열 하나**의 경우 제목이 전혀 관련 없어도 연결했다. 예를 들어 ‘매출’ 차트가 ‘기온’만 있는 Excel 자료에 연결될 수 있었다. 또한 복합 제목 ‘투자 거래’에 대해 ‘투자 회수액’과 ‘투자 거래액’의 차이를 충분히 검증하지 못했으며, 자동 매핑이 실패한 차트는 사용자에게 전체 6페이지를 한 번에 수동 지정할 방법이 없었다.

## 2. v0.47에 작성한 개선

| 개발 영역 | 구현 내용 | 기준 |
|---|---|---|
| 자동 매칭 엄격화 | 1:1 임의 연결 완전 삭제; 복합 제목의 모든 핵심 토큰 일치 요구 | 단지 같은 숫자 열이라는 이유로 채우지 않음 |
| 의미 충돌 검출 | ‘매출’과 ‘매출원가’, ‘투자 거래’와 ‘투자 회수’를 구분 | 추가 핵심 재무지표 단어가 다르면 자동 연결 거부 |
| 매칭 점수 및 동률 처리 | 정확 문자열·제한적 동의어·안전한 접미어·복합 토큰 가중 점수 | 2개 유사 수치열의 차이가 부족하면 둘 다 보류 |
| 국문·영문 제한적 대응 | Revenue, Sales, Investment, Exit, Operating Expenses, Net Income, Growth, Margin 등 | 명확히 정의된 지표만 제한적으로 자동 대응 |
| 미매칭 검토 | 자동 추천이 전혀 없어도 각 차트·수치열을 검토표에 표시 | **자동 연결 0건** 상태에서 사용자가 직접 열 지정 가능 |
| 차트별 수동 매핑 | 차트별 드롭다운에서 Excel 범위 내 열 직접 지정 → 다시 검토 → 적용 | 선택만으로 보고서 값이 즉시 바뀌지 않음 |
| 표본 한계 보완 | 최초 256행에서 숫자로 분류되지 않은 열도 **수동 후보**로 표시 | 전체 데이터 검증 성공 시에만 적용; 문자/결측을 0으로 대체하지 않음 |
| 브라우저 입력 안전 | 매칭 후보·보고서·열 제목은 `textContent`를 통해 표시 | 셀 내용·헤더에 HTML이 있어도 실행하지 않음 |
| 수정 중 충돌 거부 | 계획 수립 시 기존 차트 원본 스냅샷 저장, 적용 직전 비교 | 제목·위치·크기·스타일이 수정되면 전체 일괄 적용 취소 |
| 출처 기록 | 원본 파일명·시트·범위·값 열 제목·수동/자동 여부 기록 | JSON 저장·재열기 및 독립 HTML 차트 `source`에 남음 |
| 기존 기능 유지 | 동일 회사 묶음 ID 격리, 360포인트 데이터, 차트별 그룹·누적 집계, 자동 생성 실패 시 원본 보존 | v0.46 코드 위에 통합, 20종 갤러리 구조는 불변 |

**지표 매칭 점수는 추천 근거 설명용이며, 원본 디자인 복원율 또는 통계 정확도(%)를 뜻하지 않는다.**

## 3. 사용자 편집 흐름

1. 보고서 편집기에서 원하는 회사의 **현재 6페이지 묶음**을 연다.
2. 데이터→모션 차트·표에서 XLSX/CSV를 업로드하고 시트·셀 범위를 지정한다.
3. **현재 회사 6페이지 · 제목이 맞는 차트만 자동 연결**을 누른다.
4. 매칭 검토표에 페이지·차트 제목·추천 열·보류 이유가 나타난다. 확실한 숫자 열이 없으면 자동 제안 자체를 하지 않는다.
5. 필요한 차트에 한해 **수동 열 지정** 드롭다운으로 다른 열을 선택한다.
6. **다시 검토**하여 해당 열의 원본 데이터 전체를 계산하고, 음수 도넛·결측·수식 캐시 부족·360점 초과 등을 확인한다.
7. 전체 검토에 통과한 결과만 한 번에 적용한다. 검토 후 차트의 위치·색·글자가 바뀌었으면 적용을 중단한다.
8. 저장/HTML 내보내기에서 원본 파일·시트·범위·값 열 이름과 수동 선택 여부를 확인한다.

## 5. 코드 모델 점검(실행·범위 구분)

현재 응답 내 V8 JavaScript 모델 실행으로 다음을 점검했다.

- 한글 2열 투자·회수 차트 연결과 음수·0 보존
- 영어 Investment/Exit 대응
- 관련 없는 기온 열과 매출 차트의 자동 연결 거부
- 작성자가 기온 열을 *명시적으로* 지정한 경우에만 수동 연결
- 중복 회수액 열의 자동 동률 보류
- 동일 회사 6페이지 두 묶음 격리
- 연결 이후 source 파일명·헤더·선택 방식 보존
- 검토 후 차트 텍스트·위치가 수정되면 적용 거부
- 9,100셀 대용량 통합문서의 선택 결과 182셀 보존 및 독립 HTML 출력
- 수동 지정된 문자 열 거부, 다른 유효 데이터 연결 유지

검증 기록은 **소스 모델 시나리오**로만 분류한다. 전체 Node 테스트/브라우저 실기 검증이나 실제 50 MiB XLSX/3,000,000셀 메모리 테스트 통과를 주장하지 않는다.

## 6. 수기 실기검증 사전 체크리스트 — **아직 실행하지 않음**

1. **최신 SHA 배포:** 사용자가 실기검증을 요청하는 시점에 GitHub `main` 최신 커밋을 확인하고, Vercel 또는 Cloudflare의 올바른 DoCut 프로젝트에 1회 수동 배포한다. 배포 SHA·도메인·READY 상태를 대조한다.
2. **20종 × 6페이지:** 19개 네이티브 회사와 1개 UBS를 각각 열고, 16:9 프레임·본문·표·차트·각주·저장/재열기 상태를 확인한다.
3. **안전 자동매핑:** ‘매출’ 차트에 ‘기온’만 있는 데이터 넣기 → 자동 추천 0건이어야 한다. ‘투자 거래/회수’와 Investment/Exit는 구분 연결되어야 한다.
4. **수동 검토 UI:** 자동 추천이 없는 페이지에서 직접 열을 선택해도 바로 값이 바뀌지 않는지, 다시 검토와 적용을 누른 후에만 차트가 갱신되는지 확인한다.
5. **오류·Undo:** 중복 헤더·결측·문자·음수 도넛·잠금 차트·중간 객체 수정 시 기존 프로젝트가 유지되는지 확인. 적용 후 Undo/Redo 및 JSON 복원.
6. **템플릿 두 묶음:** 동일 회사 6페이지 두 세트를 삽입하고 두 번째에만 Excel 매핑해 첫 번째에 영향 없는지 확인한다.
7. **대용량:** 5,000셀, 9,100셀, 780,002셀, 3백만 셀 한도 근처와 XLSX 50 MiB, 수식 10,000개 환경에서 데이터가 잘리지 않고 메모리/CPU/응답성을 확인한다.
8. **독립 HTML:** Windows Chromium과 Android Brave에서 원본 출처·숫자·차트 슬롯 위치·페이지 이동·오프라인 실행 확인.
9. **UBS:** SVG 지연 로드, 기존 여섯 페이지, 텍스트 슬롯 복원, 실제 엑셀 연결, 편집 충돌 검사.
10. **원본 시각 일치도:** 공식 PDF/화면 캡처로 레이아웃·폰트·음영·벡터를 별도 정량 측정한다. **기능 코드 작성률 95%를 원본 디자인 일치율 95%로 해석하면 안 된다.**
